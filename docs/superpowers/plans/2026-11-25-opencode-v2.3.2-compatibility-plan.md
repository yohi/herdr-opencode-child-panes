# OpenCode V2.3.2 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution method requires Owner selection; no automatic execution or repeated independent review.

**Goal:** Safely visualize subagents as Herdr panes on OpenCode V2.3.2 with a shared local server and multiple root panes.

**Architecture:** Native TUI adapter owns local events and Herdr mutations. An exclusive verified server/root owner guard and passive existing-session attachment gate protect the existing pane orchestrator. Concrete host-dependent mechanisms must pass feasibility before product implementation.

**Tech Stack:** TypeScript ESM, Node >=20 baseline, npm, Vitest, Biome, tsc, tsup, zod, OpenCode public TUI Plugin API 2.3.2 and Herdr CLI.

**Spec:** [2026-11-25-opencode-v2.3.2-compatibility-design.md](../specs/2026-11-25-opencode-v2.3.2-compatibility-design.md), R0.1.0 at d05a03eebba08fc53c7ab9ca8ddd46780cb8b382.

## Review Focus

- Same root opened concurrently via equivalent endpoint aliases: one owner or both safely disabled if equivalence cannot be established (Task 2).
- Root route switches while split/attach is queued: old authority revoked, no operation on new root or reused pane (Task 2/4).
- Server restart or owner crash while managed panes remain: no takeover that duplicates/operates on unproven panes (Task 2).
- Target deleted or recreated between existence check and navigation/attribution: never create a session, reject stale target, clean only proven pane (Task 3).
- Event delivery interrupted, delayed deletion or old-generation events after reload: no stale resurrection; degraded state until authoritative reconciliation (Task 4).

### Task 2: Exclusive ownership and root isolation (T03–T05, T12)

**Files:** src/ownership-guard.ts, src/root-session-resolver.ts, src/ownership-resolver.ts, test/ownership-guard.test.ts; extend existing resolver tests.

**Interfaces:** Consumes P04/P05 proven identity and lock. Proposed internal contracts:
```ts
type OwnerKey = Readonly<{ serverIdentity: string; rootSessionId: string }>;
type RootBinding = Readonly<OwnerKey & { paneId: string; herdrIdentity: string; generation: string }>;
interface OwnerLease {
  readonly binding: RootBinding;
  isCurrent(): Promise<boolean>;
  release(): Promise<void>;
}
interface OwnershipGuard {
  acquire(binding: RootBinding): Promise<OwnerLease | undefined>;
}
```
`isCurrent` requires actual ownership and current binding, not merely local boolean. `release` only after queued/in-flight work is quiescent or fenced. Backend primitives chosen from P05; if no safe contract, no implementation.
